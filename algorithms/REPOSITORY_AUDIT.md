## 6. Dependencies, stores and execution boundaries

`pyproject.toml` requires Python >=3.12 and directly declares PyYAML, PyArrow >=25.0.1, DuckDB >=1.5.5, NautilusTrader ==2.0.0rc5, websockets ==17.0.1. Offline research adds LightGBM ==4.7.0; desktop adds PySide6 >=6.10,<7 and PyQtGraph >=0.14,<0.15 plus PyInstaller. Both platform locks and uv.lock were inspected, with historical exact-environment evidence kept separate from this host. Do not “fix” divergence by unpinning a native adapter or installing all Torch/model stacks into the core environment.

Eight project script entries cover product/projection/desktop/public qualification/public soak/ops/agent worker/broker; their actual targets are retained in the machine inventory. Entry wrapper modules and dynamic `_import_port`/worker loading preclude casual dead-code removal. Python package/command compatibility is part of acceptance, not cosmetic cleanup.

Control `SQLiteJournal` is separate from research `OpsRepository` and agent job persistence. `consume_approval_with_intent_reservation` already commits approval, intent and reservation together; `prepare_dispatch` checks expected intent/reservation versions and persists exact command/lifecycle change. Extend that transaction for newly required control identities. Cross-store research/agent writes require durable references and idempotent inbox/outbox processing, not a fictitious transaction across separate writers.

Keep native-client retry disabled where ATLAS owns ambiguity; strict provider/venue/environment/ordinary/algo/child identities; no blind retry of possibly sent openings. One writer is a process/credential-effect ownership guarantee, not only a Python lock. Multiple protected positions do not permit multiple native senders. GUI/chart faults cannot remove protection or become execution truth.

The official current Binance API documents conditional algo semantics and parameter exclusions; pinned SDK serialization must be qualified rather than inferred from wrapper arguments. Official current model APIs accept real time-series/covariate structures (TiRex load_model/TimeseriesType; Chronos2Pipeline; KronosPredictor), so old fixture shape normalization is not sufficient. Primary references are listed in the algorithm proposal.

This host has Python 3.12.14 and linked SQLite 3.53.1. It lacks the project's PyArrow, DuckDB, Nautilus, LightGBM and Qt environment. A small isolated pytest tool was installed outside the repository; no trading package/runtime upgrade was made. * Full source AST parsing/indexing passed; exact Git blob checks passed for all 287 source files.
* The first selected test collection was blocked by absent Hypothesis and missing audit-snapshot package initializers. These were not repository defects; the exact initializer was restored. The failed collection report is retained.
* A smaller nine-file baseline run executed **80 cases: 69 passed, 11 failed, no skips**. The recorded traces attribute ten failures to absent Nautilus' real Binance client-ID decoder and one to a fixture helper absent from the selective audit snapshot. These are author-attributed dependency/audit-coverage blockers, **not a fresh green full suite or independently proved harmless environmental failures**. A complete locked-environment rerun is still required; this correction does not certify that all eleven would pass there. No heavy native dependency installation or assertion weakening was used to hide them.
* An isolated synthetic call to the actual current `m0._fit` confirmed its robust-location versus mean mismatch. It used no training archive, network or real trading data and does not prove end-to-end admission/profitability.

Last trustworthy broader **historical R9** report: four partitions 2,924 cases = 2,913 pass / 8 skip / 3 fail.
