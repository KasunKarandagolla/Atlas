## 4. Processing contract P2: remove repeated work, bound publication

Keep capture size 16, handoff bounds, 64 descriptor ceiling/pressure reserve, raw fsync and 1.5-second maximum service gap. Increasing buffers, accepting loss, raising service deadlines and simply changing batch size are rejected.

Use a single bounded preparation process (`PublicEvidencePreparationWorkerV2`, multiprocessing spawn), with one in-flight job and one completion slot. Both belong to the current retained capture descriptor, not an additional unaccounted capture queue. It has no SQLite connection, credentials, network access, selection or state authority. Requests bind run, descriptor hash, full product/plan revisions and ordinal range. Jobs are only: parse/validate immutable raw evidence once; encode/hash/seal immutable payload/metadata blocks. Transfer paths/descriptors and bounded headers, not whole raw arrays through IPC. Validate existing extent size/hash limits; split metadata into <=4-MiB decoded chunks, <=512 records per block, and preserve multi-block artifact reconstruction. A 1.5-s preparation-job watchdog bounds stalled file work; successful throughput must still pass the stronger sustained gate. Worker timeout/crash retains raw descriptor, blocks dependent publication and stops safely if backlog pressure demands it.

Archive seals run on this file-only process using its own segment files and existing fsync/directory durability. SQL adoption follows durable seal. No archive descriptor may become externally usable before the sole writer validates the descriptor, ordinal bindings and hashes and commits its locator/publication. Orphan seals are not evidence and are recoverable/reusable only after exact verification.

On the sole writer:

1. Adopt verified raw extent/transport identity once. Maintain a durable adoption cursor keyed `(run, capture descriptor hash, frame ordinal, trade ordinal)` with preparation version and plan/product hashes. FIFO within each lane/feed remains causal; cross-lane scheduling uses bounded round-robin.
2. Apply book/epoch/continuity transitions, exact trade identity and conflict checks. Batch fetch uncached IDs with full feed/revision binding; stage identities privately in the same transaction as accepted decisions; move their public evidence into the final publication transaction. Feed identity must include venue, environment, product, symbol, revision and channel, matching existing semantics. A proven complete lookup returning absent permits acceptance; missing/incomplete lookup never does. Preserve repeated acquisition receipts and conflicting payload evidence. Never use a Bloom filter or cache absence as exact proof.
3. For new decisions record actual computation start/finish and sample logical availability after the state calculation, never reuse service-entry `now_ns` as completion. Persist those timings in the cursor for deterministic replay; historical logical bytes/times remain immutable. Build each logical decision once; reuse canonical bytes/hashes for block encoding and validation. A prepared ordinal map replaces O(entries x rows) archive searches. Batch descriptor/feed/header lookups and insertion with `executemany`; one composition transaction per bounded slice, no per-row savepoint. Nested atomicity remains available for genuinely independent composed operations.
4. Accumulate multiple frames in each service slice; slice at frame boundaries or trade boundaries for a large trade frame, at most 64 trades per slice, checking the existing 50-ms cooperative budget between records. Encode/seal one shared metadata block set for the slice, not one file/worker round trip per trade or frame. Commit staging once for the slice and all completed-frame publication receipts together in one final transaction; do not introduce per-frame fsync/commit amplification. Persist cursor/staging progress together. All staging stays in private control tables/files. Final public insertion atomically installs only complete frames, verified locators, block descriptors and continuity/checkpoint lineage; no staged header enters `artifact_index`. Stage tracker/book changes on a copy; install the staged copy only after commit, and expose the published copy only after complete public COMMIT and its durable post-commit observation. On rollback, state and cursor do not advance. A slow individual commit is measured, not concealed by the cooperative budget.
5. Preparation of the resulting metadata block can occur between slices; the writer services other ready work while waiting, but does not advance the same feed beyond its uncommitted predecessor. Use the final-public-insertion contract below. Logical availability is computation/input readiness, not a COMMIT timestamp. Only after successful public COMMIT returns sample `post_commit_observed_at_ns`; persist its observation before downstream decisions/effects. Effective causal availability is the maximum of logical/input/receipt availability and that observation. A pre-commit sample never proves commit completion. Publication after the decision deadline is ineligible; recovery never invents an earlier observation.

Raw transport is the canonical frame body. New interpreted L2/continuity blocks reference its exact ordinal and persist lossless interpretation metadata; do not store another copy of raw frame bytes solely for a second archive. Keep all old L2 archives/readers. Validate once per verified extent/block per bounded immutable-descriptor cache, with exact ordinal/row/hash checks; no bypass of input validation. Cache keys use immutable extent hash/location rather than unrelated segment append mtime, with replacement/corruption tests.

REST adoption currently invokes stream service between pages/products, but each invocation can itself block for a whole expensive batch. Snapshot replay can amplify this by applying buffered deltas together. Apply the same durable bounded cursor to REST page adoption and Binance snapshot/delta replay; preserve original raw receipt order, snapshot sequence proof and the existing buffer/deadline. Do not refresh the book to disguise a missed deadline. Parsing, compression, training and report generation run outside writer transactions; acceptance, duplicate/conflict decisions, chronology, book state, SQL/outbox/head updates, risk and persistence-before-effect remain solely writer-owned. Remove synchronous M1 fitting from `process_event` with a fixed-purpose isolated diagnostic worker as specified below. M0 retains its accepted estimator and bounded input population; pure fit/replay/scenario loops run outside SQL write transactions and cooperatively call stream service between rows/folds/scenario chunks, checking the original decision deadline. Seal their input set before yielding; never train on a changing population or truncate it to meet a budget.

Report/export uses a separate read-only connection/process, existing immutable manifests and bounded read snapshots. Read committed header/locator pages once, decode each block once per page, release the SQLite snapshot before Parquet compression and aggregate report work. Fix the captured cutoff and observation-qualified insertion-rowid high-water across pages. E2 shares the existing rowid cursor; private staging allocates no public rowid. Never advance a cursor past a public batch whose post-commit observation is missing or later than the export cutoff. Never let a report force writer checkpoint waits. Busy checkpoint/WAL growth triggers telemetry and admission stops, not deletion of evidence or indefinite reader pinning. A report timeout advances neither manifest nor cursor.

Recovery distinguishes maintenance from capture: completed durable research jobs may resume idempotently; an unclean capture run remains terminal/ineligible for continuity under existing run-prefix rules. ## 5. Physical evidence format E2

Set **atlas-ops schema version 2**, independent of frozen V1 journal migrations. Additive migration only, under exclusive writer fencing, transactional DDL with rollback. No historical rewrite/backfill required. New reader supports generic legacy JSON, compact-public-index V1, public-metadata-block V1 and E2 together. Old binary refuses schema 2 before writes; no automatic downgrade. Keep original logical artifact types, refs, canonical domain hashes and availability semantics; physical format marker is not returned as domain metadata.

Concrete E2 layout:

- Immutable raw bulk HTTP blocks contain each complete `PublicHttpResponseV2.raw_body`, including every metadata pagination response, envelope, row order and unmapped/rejected rows. Header records exact request method/path/query, venue/environment, response status/source identity, body SHA-256, event-time basis, receipt and acquisition identity. Each response retains its own acquisition/receipt binding and one raw payload block; no new cross-acquisition deduplication layer. Instruments within that response share its raw locator.
- Every instrument observation binds full product/revision ref, response ref and deterministic JSON path/row ordinal, canonical row hash, logical observation/ref identity, event time (or explicit missingness), receipt time, publication availability, source ID and record ID. Retain malformed/unmapped classification and original response; never silently omit its existence. Reconstruction returns exact original response bytes and separately the legacy canonical observation payload.
- `public_evidence_block_v2` stores sealed extent descriptors/version, canonical block hash and bounded chunk/record counts. Lossless Arrow IPC blocks store type/catalog columns and canonical UTF-8 metadata fragments in record/fragment order, using block compression to share repeated bytes; use the existing extent codec and limits, with no custom lossy field-elision codec; every reconstructed logical object must hash identically to its expanded form. Continuity decisions, per-instrument universe observations and universe/workset snapshots use this representation. Large legal worksets span chunks; an old 8-MiB projection ceiling must not reject a legal 4,096-product object.
- `artifact_index` receives one small complete header per E2 artifact only in the final publication transaction. E2 uses the existing insertion-rowid inventory/export cursor; there is no E2 publication-sequence namespace. `metadata_json` contains only the E2 marker/locator. `public_evidence_locator_v2` binds header ref to block/chunk/ordinal range, numeric instrument/feed catalog IDs, source/acquisition/record ID, event/receipt/availability and raw locator. Required indexes: exact ref; source+record identity; instrument/revision+event+availability for cutoff lookup. Do not repeat product JSON, raw body, state projection and ref arrays in SQL expression indexes. Rebuild affected partial JSON indexes in the schema-2 migration with an explicit E2-marker exclusion so they contain legacy rows only; E2 queries use typed locators.
- `public_trade_identity_v2` is the exact full-feed/revision + venue trade-ID -> first payload hash/ref/availability ledger, with sticky conflict evidence. Its completeness boundary is explicitly bound to retained run/feed evidence; resume readers may reconstruct from older archives before declaring complete. No invented completeness for legacy runs.

Per-instrument locators still grow linearly with required observations; “bounded” means bounded record width, block sizes, caches and processing windows, not deletion or constant lifetime storage. Every 10-second receipt remains queryable. Products are interned by exact immutable revision; do not deduplicate observations solely because values stayed equal. Reuse existing block/extent primitives rather than introduce another database or generic storage framework.

**Final E2 publication contract (supersedes the initial staged-public-row design):** `public_evidence_stage_v2` and `public_adoption_cursor_v2` are private writer control tables; staged blocks/identities/headers never enter any public evidence table, `artifact_index`, view, getter or export. Durable file seals alone are not public evidence. When a bounded batch is complete, the sole writer atomically inserts its public blocks, locators, identities, immutable `PublicEvidencePublicationV2` manifest and complete headers into `artifact_index`, plus retires private staging. Every direct SQL reader therefore sees either no new batch or its complete committed batch. No reader-specific exclusion predicate is needed to hide staging.

Logical domain availability and hashes remain immutable. The public transaction records its ID/ref set and rowid range, without claiming an actual completion timestamp. Visibility begins at successful COMMIT; a timestamp sampled before it is only a preparation sample. After COMMIT returns, sample `post_commit_observed_at_ns` (a conservative observation, not the exact commit instant) and durably record `PublicEvidencePublicationObservationV2` in `public_evidence_publication_observation_v2` before exposing the published state or any dependent decision/effect. Group all observations for the completed batch in one control commit and include that durability cost in the early benchmarks; no per-frame observation fsync. Effective availability is `max(logical availability, prerequisite/receipt availability, post_commit_observed_at_ns)`. Complete public evidence lacking this durable observation is causally unqualified: repository cutoff/source queries, dependent-input checks and causal direct SQL must require the observation join and effective availability <= cutoff. Generic noncausal getters may inspect complete bytes but cannot certify availability from the logical timestamp alone. Export exposes both times; no canonical header/domain timestamp is rewritten.

Correctness cases: rollback/failed public COMMIT exposes no partial batch and installs no published in-memory state; if COMMIT outcome is uncertain, reopen and verify the entire deterministic publication ID/ref/hash set before proceeding. A partial/conflicting set quarantines. Crash before publication leaves only private staging; restart revalidates it and inserts a new public batch at fresh rowids. Crash after public COMMIT but before durable observation preserves the complete batch and records a fresh recovery-time observation, never the earlier preparation sample. Existing observations are reused immutably. Late observation excludes the batch from earlier cutoffs/deadlines. Exact pre-existing public aliases reuse their first rowid/observation without retiming; only genuinely new artifacts allocate rowids. Failure to persist observation blocks dependent consumption and prevents cursor advancement; it cannot undo or resend the public insertion.

All E2 headers use the existing insertion-rowid cursor. Export fixes the cutoff/high-water and caps that high-water before the first batch without a durable observation or whose effective availability exceeds the cutoff; it must not skip that batch and advance beyond it. Later publication/observation is discovered at later eligible cutoffs; interruption advances neither manifest nor cursor. Keep only the pre-existing old compact-index cursor namespace needed for older-run compatibility; add no new E2 cursor. Tests cover generic/header/batched/type readers and representative direct SQL observing private staging as absent, atomic publication, rollback, ambiguous/failed commit, restart on each boundary, delayed observation and repeat export without omissions/duplicates.

Keep the **10-second full-market cadence**, request/population/history/enrichment bounds and scanner missingness semantics. The architecture must earn that cadence at the selected breadth. If measured capacity fails, reject that run configuration; a lower explicitly selected breadth is a separate profile requiring its own measurement. No automatic slower cadence or undocumented universe reduction.
