# Windows public research run

The [closure ledger](ATLAS_FINAL_DEVELOPMENT_CLOSURE_V1.json) is the development verdict. The [validation record](SESSION037_OFFLINE_VALIDATION_V1.json) identifies the tested source and installer. Use the installer attached to that exact GitHub Windows build; compare its SHA256 with the release manifest. Native Windows Server CI does not certify the owner's fresh Windows 11 laptop. The diagnostic installer is unsigned.

1. Install the per-user `ATLAS-…-win11-x64-setup.exe`, then open ATLAS. Python, Git, pip, WSL and compiler tools are unnecessary on the laptop.
2. Choose a research data folder with enough free space. Keep it outside the installation directory and outside cloud-synchronized or network folders. The application stores runs and retained evidence here; normal uninstall preserves them.
3. Leave **Intelligence disabled** for a public run without a provider secret. Select the optional accepted DeepSeek critic only when its separately governed provider configuration is intended. A stored key alone does not enable it. **Store optional DeepSeek key securely** uses Windows DPAPI; never paste secrets into run files or reports.
4. Select **Create run**, then **Start / resume**. The run selector identifies the immutable configuration and source. Status reports process/source/provider state, decision count, disk free space and DB/WAL size. Missing evidence remains visibly unavailable.
5. Select **Export report** while collection continues. Automatic exports occur every six hours under the default run configuration, and shutdown also attempts an export. Reports are in the selected run's `reports` folder. Parquet partitions and checksum manifests are the structured tuning dataset; JSON summaries are convenience outputs. Additional backlog or evidence beyond an export cutoff is explicit; export again to drain supported subsequent pages.
6. Select **Stop** for a clean shutdown. Select the same run and **Start / resume** to resume under the same source/configuration when valid. Offline gaps and restart epochs remain evidence; resuming does not establish uninterrupted endurance or repair past decision availability. A different source/configuration requires a new run.

A fresh public run can begin collecting immediately but cannot invent prior observed history, trained model support, complete event calendars, account-specific fees or qualified fills. Expect warmup and `NOT ESTIMABLE` cases until the declared prerequisites exist. Diagnostic price labels, source/feature health, registered origin accounting, missingness, latency and pressure remain useful. Supported action economics and lifecycle evidence have their own explicit evidence gates; candle returns are not executable payoff.

During a 48-hour-or-longer diagnostic run, inspect the compact report for source gaps, expected/received origins, rejection reasons, feature/regime missingness, registered method identity, prediction errors as horizons mature, exact-action M0/M1 differences where supported, lifecycle/cost support and backlog/resource pressure. Unregistered origins and absent independent samples stay unknown. Keep raw archives and their index together for reconstruction; do not manually modify `ops.sqlite`.

This guide does not authorize starting a live campaign. The first owner-hardware run still qualifies installation, environment and source behavior. It does not establish profitability: positive economic claims require at least eight genuine prospective weeks, 200 matured opportunities, adequate regimes, dependence-aware inference and the other frozen gates. Capital and assisted execution remain disabled.
