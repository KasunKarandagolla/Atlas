# Session 018 evidence capability audit

**Matrix:** `EVIDENCE_CAPABILITY_MATRIX_V1.json`, schema version 1, 16 required evidence families. Each row declares source/channel, product scope, fields and units, cadence, sequence/update meaning, timestamps, raw retention, gap behavior, observed coverage, limits, permitted and prohibited uses, and frozen status vocabulary. Matrix status describes repository/offline evidence. It does not promote a public feed or a strategy.

## Actual repository coverage

Session-012 collection is credential-free REST: Bybit instruments, final bars, recent trades, ticker BBO/mark/index/current funding/OI, funding history and OI history; Binance USD-M exchange info, final bars, aggregate trades, book ticker, premium index, funding history and OI. `RawObservationV2` hashes exact response bytes and keeps actual HTTP response receipt separate from source event/publication time. The collector archives Parquet before indexing, persists source health, demotes prior healthy state on restart, and supports overlap/duplicate checks. Its bounded Session-012 public run proved REST endpoint and short overlap behavior only. No later session changed `src/atlas/v2/data/` before Session 018.

The pre-existing collector has a generic integer `sequence_is_contiguous` option. That does not by itself establish a venue-specific depth book: a REST BBO snapshot lacks a diff chain, Bybit `seq` can be nonconsecutive, and Binance depth events use ranged IDs and `pu`. Session 018 therefore adds a separate typed Binance USD-M depth bridge. It accepts exact `GET /fapi/v1/depth` bytes and externally supplied `depthUpdate` frame bytes, records real caller-supplied receipt time and raw hashes, validates snapshot bridge and `pu` continuity, and requires a new snapshot after a gap, reset, disconnect or process restart. It archives before recording its cursor index. A cursor is audit evidence; restart never treats it as a live book. **No WebSocket transport is attached or qualified.** No live sequence-valid L2 coverage is claimed.

Bybit V5 trade and all-liquidation frame capture accepts exact caller-supplied bytes and checks symbol, documented trade ID/taker side and liquidation position side/size. Official raw material capture accepts exact bytes, source ID, publication claim, receipt time and optional revision link. Both are collection-only typed boundaries; no live feed or official source has been connected. The liquidation feed may be censored or interrupted. A captured frame does not establish a complete interval. These paths deliberately keep source health incomplete.

Missing evidence: continuous sequence-valid L2/BBO; complete aggressor-trade coverage; live liquidation feed and coverage proof; useful continuous OI/funding/basis/mark/index/last observation cadence; next-funding revisions across time; official venue/news collection and deterministic extraction completion; continuous point-in-time metadata/filter revisions; account fee revision history; clock-drift/latency bounds; measured disconnect/offline intervals; declared L2 retention and sampled control cohort. Current REST history cannot recover historical ATLAS receipt times, prior funding predictions, L2, liquidation messages or an event body that was never captured. Candle volume is not order flow. Missing resolution blocks S4/S5/event inference.

## Source rule and semantics

The pinned Nautilus public adapter was inspected in Session 012 and exposes typed Bybit data methods. Its normalized events were unsuitable for exact raw payload and ATLAS receipt provenance; Binance lacked the needed public read helper. Session 018 retains the narrow credential-free HTTP client for the depth snapshot and adds no authenticated or order-capable SDK. The new frame boundary needs an independently qualified credential-free WebSocket source before it can collect live frames.

Official primary source semantics consulted during the audit: [Binance USD-M local book procedure](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/How-to-manage-a-local-order-book-correctly), [Bybit orderbook](https://bybit-exchange.github.io/docs/v5/websocket/public/orderbook), [Bybit public trade](https://bybit-exchange.github.io/docs/v5/websocket/public/trade), [Bybit all-liquidation](https://bybit-exchange.github.io/docs/v5/websocket/public/all-liquidation). Bybit public-trade `S` is taker side; all-liquidation `S` is the liquidated position side. A liquidation `Buy` means a long position was liquidated. Those meanings are not interchangeable. Bybit `seq` orders book events across depths but is not a simple contiguous increment for the regular orderbook channel. Binance USD-M depth uses snapshot and ranged stream IDs, with `pu` continuity for subsequent futures updates. Endpoint documentation does not qualify this environment's live transport or historical completeness.

## New contract boundaries

`MaturedOutcomeV2` version `MATURED_OUTCOME_V2_V1` is immutable, canonical and SHA-256 addressed. It binds candidate/set/decision identity, policy ID/version/hash, optional exact frozen action hash/artifact with an explicit absence reason, instrument revision/venue/product, decision/horizon/maturation/availability, label definition/view, signed USDT payoff components and contract-unit fill quantities only where measurable, signed MFE/MAE only with a separate extrema evidence ref, evidence resolution/quality/ambiguity, and `ACTUAL`, `SIMULATED` or `COUNTERFACTUAL` provenance. Matured no-fill/partial/full-fill states require measured execution evidence and quantities. A positive executable fill requires a frozen action and execution evidence; an unfrozen rejected/unselected candidate cannot claim a matured executable payoff. `UNRESOLVED`/`CENSORED` carry no measured payoff. `ACTUAL` uses `ACTUAL_SYSTEM` view and, if matured, an indexed `ActualClosedPositionSourceV2` already qualified by the existing reconciled execution/account PnL source path. `SIMULATED` and `COUNTERFACTUAL` are research only. The index refuses maturation before required evidence becomes available; training cutoffs use the label's own availability. The calendar enum retains selected, unselected, rejected, no-candidate, no-trade, not-estimable, expired, no-fill, partial-fill and full-fill states. No M0 fitting was added.

`PretradeScenarioArtifactV2` version `PRETRADE_SCENARIO_ARTIFACT_V2_V1` binds exact frozen action/artifact, cutoff, model/calibration/source/execution vintage refs, common joint scenario set, joint payload identity, support, separate uncertainty/dispersion refs, deterministic stress refs, creation/computation/availability/expiry, and explicit `AVAILABLE` or `NOT_ESTIMABLE`. Every causal source/model/calibration ref must be indexed and available by cutoff. Replay/payoff/matured outcome kinds cannot enter as causal inputs. Payloads are distinct immutable joint rows covering price/mark/index, spread, depth/liquidity, fill state, decision-to-execution latency, exit latency and funding. Exact Decimal row weights sum to one. Deterministic stress has no probability weight. More rows mean numerical resolution, never more historical observations. `NET_CASHFLOW_ONCE_V1` is the only supported cost convention; the downstream generator/evaluator must account for executable spread/impact, fees and funding once in a joint row. Scenario generation, support scoring, uncertainty estimation and economics remain `TEST GATE`.

The existing schema-version-1 `EvaluationArtifactV2` in `contracts.py` predates the amendment. Its `scenario_manifest_ref` and `common_path_ids_ref` can refer to retrospective replay and are **not** a decision-time `pretrade_scenario_ref`. Session 019 must add a distinct versioned evaluation contract/read path with expected net value and lower bound, separate estimation/execution/numerical uncertainty, support/calibration/OOD, outcome distribution, ES before/after, and final `CANDIDATE | NO_TRADE | NOT_ESTIMABLE` admission. Old records must retain their old meaning and fail closed at the amended gate. Session 018 does not create a TradePlan or capital authority.

## Inclusion and retention rule

An observation is evidence only for the instrument, channel, time, source health and actual archived raw bytes it covers. A decision-referenced payload must remain retrievable. An unreferenced raw L2 retention policy and sampled control cohort remain `TEST GATE`; no implied broad coverage is created by the matrix. The live-control V1 SQLite is untouched; `ops.sqlite` schema version 1 remains a single-writer operational index, Parquet retains raw payloads, and DuckDB remains analytics-only.
