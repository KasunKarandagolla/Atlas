**CONFIRMED source path:** capture Arrow encode/compress -> raw extent fsync -> capture-journal receipt fsync -> retained descriptor -> writer reread -> PARSE input/result -> private stage FULL commit -> copied writer book/tracker state -> interpretation -> SEAL rereads raw and constructs another Arrow raw archive -> worker result fsync -> public SQL transaction -> install state. A single warm diagnostic profile of 16 already parsed trade frames, with no SQL/archive I/O or live lanes, produced 48 artifacts, 160 `sha256_json` calls and 112 dataclass replacements. `_persist_tracker` accounted for 195.5 ms of 256.9 ms profiled interpretation; hashing/canonical conversion and immutable-map construction were major descendants. ## 2. Chosen correction: captured raw once, bounded SQL transitions

Implement in this order; retain one descriptor, one preparation process, one in-flight job and one completion. Do not add another queue or process.

### A. Raw locators; no second seal for captured stream frames

In `broad_public_runtime.py` and `microstructure_archive.py`, replace captured WS raw duplication with a lossless frame-view manifest. Each row binds run, transport batch/extent hashes, exact FIFO ordinal, full product/revision/feed, connection epoch, raw SHA-256, receipt/event/domain availability and all current `L2RawFrameV2.metadata_dict()` fields. A Bybit trade additionally binds its original JSON row ordinal; Binance binds the aggregate-trade row and retains aggregate ID/range semantics. Identical receipts and conflicting payload receipts remain distinct observations.

Keep current frame `record_id`, sorted group order and `L2RawFrameChunkV2` chunk-ID recipe. The final publication installs a small frame-view block plus a checkpoint with the existing `L2FrameArchiveCheckpointV3` logical body/hash. `archive_extent_ref` continues to identify `extent_ref("ops-l2-frames", chunk_id)`; its **new physical descriptor** is `PublicArchiveFrameViewV1`, naming the captured extent and row map. Store that small physical descriptor as canonical `{"view": ...}` metadata in its own header, with publication binding in the typed locator; construct it after the row-map block hash. It is not part of that block's hash preimage, avoiding a circular reference. Never pretend it is a `PublicArchiveExtentV1` with nonexistent bytes. Exact pre-existing descriptors/checkpoints retain their first rows/timings after logical row/body comparison; never replace or retime them.

Extend `public_archive_extents.py::read_public_chunk/read_extent` and `L2FrameArchiveV2.read_chunk` to dispatch that descriptor, reconstruct the same Arrow rows/raw bytes and validate hashes, ordinals and counts. Compatibility consumers in `compact_public_index.py` must use this dispatcher rather than assume a physical L2 extent type. Reader caches are bounded to eight verified immutable blocks/extents, keyed by descriptor/content/location, not segment append mtime. Appends never modify a cached prefix; replacement/truncation/mutation invalidates or fails verification on reopen. Missing/corrupt transport fails closed. Raw referenced by retained evidence cannot be deleted.

Captured book frames use the same view; writer book acceptance/sequence proofs stay unchanged. REST snapshots without a capture locator retain their existing durable archive path. This authorizes no new snapshot/replay policy. Normal captured-descriptor adoption submits **PARSE only**, with no archive SEAL round trip. SEAL remains available for legacy/non-captured callers.

### B. Lossless continuity blocks and a writer-owned slice kernel

New `data/public_stream_evidence_v1.py` defines `PUBLIC_STREAM_SQL_BLOCK_V1`: canonical UTF-8 JSON, optional existing zlib level-1 compression, SHA-256 of decoded bytes, explicit decoded/encoded lengths, <=4 MiB decoded and <=512 records. Compression is used only if smaller. Use this medium for small stream interpretation/health/frame-view metadata only; broad HTTP/universe/workset Arrow E2 is deferred.

A self-contained block holds interned exact feed/product context, an initial **cache-free scalar projection** per feed, and ordered observation records containing frame/trade ordinals, exact variable observation fields, classification/reason, sparse scalar-field assignments and existing observation/state/artifact refs. Assignments are absolute values, including explicit nulls, not arithmetic deltas or implicit defaults. Static fields come from the immutable context; changed fields must be in a closed schema. Every intermediate `BroadPublicStreamContinuityV3` body reconstructs byte-for-byte, including its current empty caches and projection completeness rule. A block starts with a full projection, so point lookup replays at most 512 records and never a lifetime chain. Do not emit a new domain continuity version or lose a receipt, duplicate, gap or conflict.

Add `apply_slice_v2` on a private writer-owned continuation: validate external observation fields/feed binding once; apply the existing `apply_deferred` transition rules in order using one private scalar/cache accumulator; emit each classification and projection change; freeze the final tracker once per distinct feed. Preserve replay-cache checks, availability ordering, epoch transitions, receipt maxima, event regression, cache eviction/completeness, gap history and sticky conflicts exactly. The existing V1 tracker remains the reference implementation and public API. Fork each distinct book/feed **once per descriptor**, never once per frame. Persist one bounded operational checkpoint per affected feed/publication (including bounded replay/identity cache state); it is separate from per-observation cache-free domain projections.

Exact hashes still require exact canonical preimages. Cache immutable canonical field fragments, build each observation/projection/body's canonical bytes once, and reuse those bytes for SHA-256, block encoding and equality. A private validated-byte record replaces generic `ArtifactIndexEntryV2`/`FrozenMap` construction in this hot path; generic objects are hydrated on read. Do not use a caller-provided hash as validation or bypass strict external decoders. Byte-level parity, including Unicode/null/decimal/field ordering, is mandatory before this path is enabled.

### C. Minimal E2 SQL publication and exact trade ledger

`memory/repository.py` owns `lookup_trade_ids_batch_v2`, `publish_stream_slice_v1`, `observe_publication_v2`, `effective_available_at_ns` and the format-aware decoder. Batch-fetch full-feed/revision trade identities once per <=64-trade writer slice; merge with earlier private identities in that slice. Pass known hash, lookup completeness and sticky conflict to the transition kernel. An empty cache is not absence proof. Ledger completeness is evidenced for the retained run/feed prefix; legacy history needs verified reconstruction before claiming completeness. First payload/ref/availability stays immutable; conflicts append evidence and latch conflict. No second SQL writer.

Public tables keep R1 names: `public_evidence_block_v2`, `public_evidence_locator_v2`, `public_trade_identity_v2`, `public_evidence_publication_v2`. The block table adds a discriminated `SQL_STREAM_V1` payload/digest/length variant alongside the reserved Arrow extent variant. Headers remain in `artifact_index` with one small E2 marker/locator per original logical artifact and the existing insertion rowid. Intern exact feed/product revisions; typed ref, feed/time/availability and trade-ID indexes replace repeated JSON expressions for these rows. Exclude E2 markers from relevant legacy partial JSON indexes.

One bounded, complete slice uses one public transaction for blocks, all headers/locators, identity decisions, frame-view/checkpoint, manifest and control retirement. Fetch existing headers/locators/catalogs once; compare immutable content before `executemany`; no per-entry savepoints, generic known-row hydration or archive rescanning. Preserve external `atomic_composition` rollback semantics. Private implementation methods require the already-owned connection/transaction and may not commit independently. New computation records sample writer start/finish and logical readiness after state calculation, at or after prerequisite readiness; worker timestamps and service-entry `now_ns` cannot authorize that readiness. Retain original timings for already durable stages/aliases. Parity tests fix identical logical timestamps explicitly; they do not backdate new computations to reproduce an old hash.

**Explicit R1 correction:** a complete, bounded slice need not first commit a redundant private stage. Its atomic public transaction is the durable completion. Partial frames or a slice that must yield persist the complete verified logical input/output, original computation timings, private state and cursor in `public_evidence_stage_v2` before releasing that state; publication waits for the whole frame. Do not retain an unbounded list of a large frame's trades: use <=64-trade slices and <=512-record blocks, with frame-completion publication across its privately prepared blocks. Cursor advancement, state and identity staging commit together. Worker PARSE output is atomically replaced/hash-bound **rebuildable scratch**, with no result-file fsync; no durable cursor may depend solely on that scratch. Lost unpublished scratch is regenerated from durable raw. Durable stage payloads retain all exact inputs/timings needed to reproduce them. Raw extent/journal fsync and FULL SQL durability stay mandatory.

After public COMMIT returns, sample the conservative post-commit observation, then persist it in the owner-writable `public_evidence_publication_observation_v2` with **one grouped FULL control commit**. Only then install the published state/count indexed frames or allow dependent decisions. Observation rows are immutable and readable on authorized read-only connections; worker/readers cannot write them. Keep `effective = max(logical, receipt/prerequisite readiness, observed time)` and missing observation = causally unavailable. A pre-COMMIT timestamp is never completion proof.

## 3. Version, readers and recovery are part of the prototype

Use **ops schema 3**, not another incompatible schema-2 interpretation: the current schema is already 2 with only private adoption tables, and its binary would otherwise open an incomplete replacement as the same version. Additive fenced transactional migrations 1/2 -> 3; rollback/reopen tests; no historical rewrite/downgrade. New reader supports old schemas/formats; version-2 binaries refuse schema 3 before writes. New preparation requests/results use `PUBLIC_EVIDENCE_PREPARATION_V3`, with exact transport locators instead of base64 raw copies; retain V2 decoding for existing stages/results. Do not reinterpret their hashes or timestamps. Stage-free recovery applies only to new V3 complete slices.

Before enabling E2 writes, implement decoder parity through repository generic/header/batched/type/page APIs, frame/trade/history/continuity queries and applicable direct SQL. `chronology.py::causal_artifact/record_computation`, `broad_export.py::_refs`, and `tuning_export.py` inventory/cutoff/export paths must consume the publication observation. Keep domain header timestamps/hash checks separate from `effective_available_at_ns`; generic noncausal inspection of a complete unobserved batch cannot certify causal use. Direct causal queries join the observation. Export emits both chronologies and caps its fixed rowid high-water before the first unobserved or cutoff-late batch; it never skips past it. No new export cursor namespace.

Rollback exposes no partial frame and installs no state. Ambiguous public commit: reopen/verify the complete deterministic ref/hash set before proceeding, quarantine a partial/conflicting set. Crash after public commit but before observation: retain that complete batch and record a fresh recovery-time observation; never republish/retime existing aliases. Reuse an existing durable observation. Private stages remain absent from every public reader/export. Restart may complete forensic adoption; an unclean capture still requires a new run and snapshot recovery. A clean terminal receipt requires all accepted raw to be indexed and observation-qualified.

These minimal E2 pieces are F1 prerequisites: migration/decoder, SQL stream blocks, typed locators/exact IDs, private partial-frame cursor, publication observation and causal/export barriers. Full bulk-response storage, polling cycles, maximum worksets, admission certificates, intelligence/model integration and commissioning remain deferred until their planned gates.

## 4. Capacity budget and harness correction

At 160 frames/s, 16-frame descriptors arrive every 100 ms. Target **>=240 completed frames/s with backlog present**, or <=66.7 ms per complete descriptor, gives 80 frames/s excess service after a 320-frame/s one-second burst: its 160 excess frames should drain in approximately two seconds. Require recovery within five seconds in the short feasibility probe; retain R1's 20-s maximum in full F1. This target is an engineering feasibility threshold, not a relaxed frozen bound.

For the current strictly retained-descriptor chain, worker and writer stages of that descriptor are sequential. They must collectively meet 66.7 ms, even though independent capture and unrelated service can overlap. Suggested **measurement budgets**, not permissions to truncate work: PARSE/file/IPC <=15 ms mean, writer acceptance/canonical/index preparation <=15 ms, public FULL transaction <=15 ms, observation FULL transaction <=10 ms, remaining polling/validation/scheduling <=10 ms. Measure exclusive intervals and actual end-to-end publication latency; component thresholds alone cannot pass the gate. Capture plus mandatory raw/journal durability must independently sustain >=240 frames/s under this same concurrent I/O load. A 320-ms SEAL cannot meet even the 100-ms sustained budget; replacing it with smaller metadata SEALs of unknown cost is insufficient. One slot is retained until the revised end-to-end rate is measured.

Fix `scripts/session041_recovery_capacity.py` before measurements:

- Report actual offered, capture-sealed and observation-qualified indexed counts/timestamps **during producer time**, separately from stop/drain totals. Current final `captured/elapsed` can include post-stop raw drain and overstate producer-window capture rate. “Delivered” currently means a descriptor was popped, not committed publication.
- Parameterize exploratory duration/burst time explicitly and hash those actual parameters. The retained short wrapper changed duration/burst to 14 s/t=3 while profile/burst-accounting helpers retained hardcoded t=30. It remains valid failing-prefix evidence; its burst-pass fields/profile cannot qualify a run. Keep full F1 at 60 s/t=30 with the same two 80/160-frame/s lane schedules.
- Count raw accepted-but-not-published frames across handoff, capture in progress, sealed descriptors and adoption; sampled pending currently omits capture in progress. Record offered schedule error/catch-up bunching, actual trades and bytes, per-lane rates, high-water limits/floors, raw fsync/receipt fsync, worker wall/**process CPU**, writer CPU, SQL statements/savepoints/bytes, each commit and reader contention. CPU/process/thread counts alone are not attribution.
- Hash all participating source/config/lock files and fixture recipe. Warm fixed imports/processes before timing and report cold startup separately. Preserve fsync/FULL and report cgroup/affinity/quota and Arrow thread counts; no silent resource/profile changes.

Current F1 generates one trade per ~151–161-byte frame, two BTC venue keys, and no depth frames/REST/reports. It is a useful cheap lower-bound stream test. Failure there is a real runtime deficiency; passing it cannot qualify the declared mixed profile. Do not reduce even this geometry or label it full mixed capacity. F4 still proves depth/snapshot/read concurrency later.
