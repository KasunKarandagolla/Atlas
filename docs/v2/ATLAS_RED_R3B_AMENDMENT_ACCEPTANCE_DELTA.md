# ATLAS RED R3B amendment acceptance delta

**Status: REQUIRES INDEPENDENT ACCEPTANCE.** This is the narrow R3B gate delta;
it does not accept or replace the S47 proposal.

The owner-finalized target remains a small adaptive, economically supported
shortlist, a compact Decision Brief, a bounded DeepSeek-preferred final
discretionary agent choice, and independent ATLAS risk, protection, and
authorization. R3A adds only a zero-authority projection. No comparative-action
runtime or provider dispatch is enabled.

Before R3B can create an operative comparative arm, independent acceptance must
cover these exact contract changes:

1. **Comparative cohort:** which candidate/action pairs enter the arm, how the
   complete eligible and excluded population is sealed, and which exact
   immutable identities scope each alternative.
2. **Risk/economics sequence:** independent hard-risk sizing of each permissible
   alternative, freezing exact actions before action-conditioned M0/M1,
   scenario, cost, support, uncertainty, OOD, stress, and ES evaluation.
3. **Calendar denominator:** whole-screening and whole-schedule preservation,
   including no-candidate, unsupported, rejected, late, no-trade, no-fill,
   abstain, outage, and expired cases; paired A0 outcomes must use that same
   original denominator without rewriting A0 records.
4. **Failure semantics:** explicit reject-all, abstain, timeout, late-result,
   missing-evidence, outage, and expiry behavior; no implicit A0/provider
   fallback, failed-action rescue, same-slot retry, or action mutation.
5. **Immutable identity:** versioned identities for policy, cohort, brief,
   exact action, request, tool results, provider result, and paired outcome;
   exact source cutoff, availability, revision, and invalidation rules.
6. **Provider and tool authority:** independently verified DeepSeek-preferred
   model/revision, structured output and returned identity, cancellation and
   deadline behavior, token accounting and prices, retention, and the closed
   read-only tool allowlist. No shell, SQL, arbitrary code, browser, account,
   broker, or venue tools.
7. **Numeric bounds:** accepted per-job/day/month spend and explicit row, byte,
   instrument, image, token, reference, and time limits. Unknown provider price
   or capability denies dispatch; exceeding a bound blocks without truncation.
8. **Rollback:** an independently testable switch that disables only the R3B
   comparative arm and its dispatch identity while preserving A0, protection,
   outcome maintenance, and immutable receipts.
